## Актуальне рішення користувача — 02.10.2026

Останній запит прямо дозволяє завершити весь екран героя за затвердженим референсом, підключити десять нових портретів і створити потрібні дрібні частини. Вимога цього документа зупинитися після STEP 1 для поточного екрана скасована.

- Профіль героя має повністю поміщатися на один мобільний екран без прокручування.
- Робочі розміри: 375×812, 390×844 і 430×932; широке вікно лише показує центровану мобільну область.
- Гра доступна лише як Telegram Mini App; localhost лишається локальним preview для розробки.
- Зберігати оригінальні ігрові дані й обробники. Візуальну збірку робити з підготовлених 9-slice / 3-slice деталей і наданих портретів.
- Не запускати зайві тести; достатньо перевірки збірки й візуального перегляду екрана.

ПРАЦЮЄМО НАД МОБІЛЬНОЮ RPG У СТИЛІ СТАРОГО ПОЛЬОВОГО БЕСТІАРІЮ / КОДЕКСУ.

ГОЛОВНИЙ ВІЗУАЛЬНИЙ РЕФЕРЕНС:
екран героя з пергаментом, темною шкіряною основою, портретом, характеристиками, спорядженням, талантами, бойовими параметрами і нижньою книжковою навігацією.

ВАЖЛИВО:
не копіювати конкретну картинку 1:1.
Копіювати:
- композицію;
- пропорції;
- інформаційну ієрархію;
- матеріальність;
- принцип фізичних UI-елементів.

НЕ використовувати старий інтерфейс як візуальну основу.
Із старого UI можна брати ТІЛЬКИ:
- state;
- handlers;
- API;
- gameplay logic;
- дані;
- назви характеристик.

Presentation layer перебудувати окремо.

==================================================
ГОЛОВНИЙ ПРИНЦИП
==================================================

UI НЕ повинен складатися з готових великих PNG-панелей.

Він повинен збиратися з невеликого набору повторно використовуваних тайлів.

Нам потрібна система, де один і той самий asset можна використати для блока:
200×70,
350×120,
350×400,
або іншого розміру
БЕЗ неприродного розтягування кутів, рваних країв, заклепок і декору.

Тому використовуй:

1. 9-SLICE для пергаментних площин.
2. 3-SLICE для горизонтальних заголовочних стрічок.
3. Окремі квадратні reusable tiles для кнопок.
4. Окремі slots для предметів.
5. Окремі декоративні divider-и.

Не масштабуй весь PNG цілком.

==================================================
1. ПЕРГАМЕНТ
==================================================

Пергамент уже зроблений як набір 3×3 тайлів:

[ top-left ] [ top ] [ top-right ]
[ left     ] [ fill] [ right     ]
[ bottom-left ][bottom][bottom-right]

Реалізувати компонент типу:

<ParchmentPanel>
    content
</ParchmentPanel>

Поведінка:

CORNER:
- ніколи не розтягувати;
- зберігати aspect ratio;
- використовувати у натуральному масштабі або рівномірно масштабувати.

TOP / BOTTOM:
- повторювати або акуратно tile по X;
- НЕ stretch.

LEFT / RIGHT:
- повторювати по Y;
- НЕ stretch.

CENTER:
- безшовно repeat по X/Y.

У CSS бажано використовувати:
- CSS Grid 3×3;
або
- border-image тільки якщо результат реально не деформує текстуру.

Перевага — CSS Grid з окремими тайлами.

Приклад структури:

.parchment {
    display: grid;

    grid-template-columns:
        var(--corner)
        1fr
        var(--corner);

    grid-template-rows:
        var(--corner)
        1fr
        var(--corner);
}

center/edges повинні використовувати background-repeat.

ВАЖЛИВО:
центральна область не повинна мати власної рамки.

Коли два контентні блоки знаходяться поряд —
вони повинні виглядати як записи на одному аркуші,
а не як дві Bootstrap cards.

==================================================
2. ЗАГОЛОВОЧНА ПЕРГАМЕНТНА СТРІЧКА
==================================================

Стрічка повинна складатися з ТРЬОХ деталей:

[ LEFT CAP ][ REPEATABLE CENTER ][ RIGHT CAP ]

Створити reusable компонент:

<SectionRibbon title="Характеристики" />

LEFT:
- фіксований;
- не stretch.

RIGHT:
- фіксований;
- не stretch.

CENTER:
- repeat-x;
- ширина автоматично займає потрібний простір.

Текст малюється HTML/CSS поверх asset.
НЕ вшивати текст у PNG.

Таким чином та сама стрічка повинна працювати для:

Характеристики
Спорядження
Таланти
Бойові показники

і для майбутніх розділів.

==================================================
3. ЗАГАЛЬНИЙ ТЕМНИЙ КВАДРАТНИЙ TILE
==================================================

Темний квадрат із золотою/латунною рамкою — це GENERAL PURPOSE TILE.

Він НЕ є кнопкою редагування.

У самому asset:
- немає олівця;
- немає символу;
- немає тексту.

Іконки кладуться окремим шаром.

Приклад:

<SquareButton>
    <Icon />
</SquareButton>

Цей tile можна використовувати для:
- edit;
- plus;
- details;
- lock;
- menu;
- інші компактні дії.

НЕ генерувати окремий PNG під кожну кнопку.

==================================================
5. HERO HEADER
==================================================

Верхній Hero-блок має бути головною композиційною точкою.

Приблизно:

┌────────────────────────────┐
│ PORTRET │ Ім'я героя       │
│         │ клас · рівень    │
│         │ XP BAR           │
│         │                  │
│         │ 3 compact stats  │
└────────────────────────────┘

Портрет:
~35–40% ширини контентної області.

Праворуч:
- ім'я;
- клас;
- рівень;
- XP;
- ключові hero parameters.

Не будувати праву частину з 10 вкладених containers.

==================================================
6. ХАРАКТЕРИСТИКИ
==================================================

Один великий parchment section.

НЕ створювати 6 окремих карток.

Використовувати 2 колонки.

Приблизна структура рядка:

[icon] Назва
       короткий опис           VALUE [+]


Приклад:

Сила                 7   +
Фізичний урон

Ловкість              9   +
Швидкість і ухилення

І т.д.

Між записами:
- whitespace;
- або тонкий divider.

НЕ рамка навколо кожного параметра.

Іконки:
- сила;
- ловкість;
- інтелект;
- живучість;
- удача;
- дух.

Використовувати вже наданий набір іконок.

==================================================
8. ТАЛАНТИ
==================================================

SectionRibbon:
ТАЛАНТИ

Горизонтальна смуга:

[skill][skill][locked][locked][locked]

Unlocked talent:
- art/icon всередині slot.

Locked:
- той самий базовий slot;
- поверх нього окрема lock icon.

НЕ малювати окремий locked-slot PNG, якщо це можна коректно зробити композицією.
